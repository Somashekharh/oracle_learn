Oracle Security & Hardening

Build secure-by-default Oracle environments with least privilege, auditing, and hardening controls.

User Privileges and Roles

Apply least privilege with role-based grants and periodic entitlement reviews.

CREATE ROLE app_readonly;
GRANT CREATE SESSION TO app_readonly;
GRANT SELECT ON hr.employees TO app_readonly;
GRANT app_readonly TO analyst_user;

Auditing Basics

Track sensitive activity and policy violations with unified auditing in Oracle.

CREATE AUDIT POLICY dba_changes
ACTIONS ALTER USER, DROP USER, GRANT;
AUDIT POLICY dba_changes;

SQL Injection Prevention

Use bind variables, input validation, and controlled privilege boundaries in application schemas.

SELECT * FROM accounts WHERE user_id = :id;
-- Avoid concatenated dynamic SQL with user input

Database Hardening Checklist

  • Disable unused accounts and lock default users.
  • Enforce strong password profiles and rotation windows.
  • Encrypt sensitive data at rest (TDE) and in transit (TLS).
  • Review PUBLIC grants and revoke unnecessary access.
  • Enable auditing for privileged operations and schema changes.
  • Patch database and OPatch inventory regularly.
  • Restrict network ACLs and listener access.
